# Anchored Lock-0 ruleset decision

Date: 2026-10-27 America/Boise

Decision: retain V1 globally and isolate anchored locks in a versioned V2
ruleset. The prototype is accepted as evidence, not approved for production.

## Decision

- `binary2048-v1` keeps the shipped sliding Lock-0 behavior, global turn-parity
  lifecycle, existing `lock_block` and `lock_break` events, and all current
  deterministic outputs.
- Anchored behavior is assigned `binary2048-v2-anchored-locks`. It may ship only
  through an explicit ruleset selector and begins unranked. It must not silently
  replace V1 or inherit V1 leaderboard eligibility.
- The V2 ruleset uses per-coordinate collision counters. Number, zero, and
  wildcard tiles can trigger a collision; the second collision removes the
  lock after the current swipe resolves.

## Replay and migration policy

- Every new replay, export, recovery snapshot, simulation request, and stored
  session for anchored behavior must carry the exact V2 ruleset ID and a schema
  version. Missing or unknown ruleset IDs fail closed.
- Existing exports that omit a ruleset ID retain the legacy import behavior and
  are interpreted only as V1. They are never replayed through anchored rules.
- There is no automatic V1-to-V2 replay migration because identical directions
  can produce different boards, scores, terminal turns, events, and RNG spawn
  positions. Historical V1 results remain immutable.
- A future scenario-authoring conversion may copy an initial board and seed
  into a new unranked V2 scenario, but it creates a new game identity and is not
  a replay or score migration.
- Recovery must restore per-lock counters and RNG state. A V1 recovery cannot
  be upgraded in place; a V2 recovery presented to a V1 engine, or vice versa,
  is rejected.

## Event semantics

- `lock_collision` records the lock coordinate and resulting per-lock collision
  count for every collision attempt.
- `lock_removed` records the same coordinate and terminal collision count. It
  follows `lock_collision` in the event list and occurs after line resolution,
  so the incoming tile remains adjacent during that swipe.
- V2 does not reuse V1 `lock_block` or `lock_break`: those names imply the old
  parity and zero-annihilation behavior and would make cross-ruleset telemetry
  ambiguous.
- Spawn, merge, win, and game-over events retain their existing meanings but
  must be generated by the selected ruleset engine and hashed with its ruleset
  identity.

## Promotion gates

Before production use, ruleset dispatch must be added to engine, API,
simulation, replay, recovery, tutorial/help, and storage schemas; V2 sessions
must remain unranked until competitive policy explicitly approves them. That
work requires a separate delivery item and is not authorized by this spike.

## Verification

- The prototype game, replay, and recovery objects carry the V2 ruleset ID.
- Imports reject V1 and missing ruleset identities.
- Tests lock event ordering, coordinates, and collision counts.
- Production modules do not import either anchored-lock prototype.
